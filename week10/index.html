3.5.1 DNS Concepts & Hierarchy
  • DNS maps fully qualified domain names (FQDNs) to IP addresses.
  • Hierarchy: Root (.) → TLD (.com, .my) → Second-level domain → Subdomain → Host.
  • Recursive query: Client asks resolver; resolver queries on behalf of client until answered.
  • Iterative query: Resolver gets referrals and must query each server itself.
  • DNS uses UDP port 53 for queries; TCP port 53 for zone transfers.
  • TTL (Time To Live) controls how long records are cached.
3.5.2 Configuring DNS on a Cisco Router
  • ip domain-lookup — enables DNS lookups (enabled by default; disable with no ip domain-lookup).
  • ip domain-name <domain> — appends domain to unqualified hostnames.
  • ip name-server <ip1> [ip2] — specifies the DNS server(s) the router queries.
  • The router itself does not become a DNS server with these commands — it only queries external DNS.
3.5.3 Configuring a DNS Server in Packet Tracer
  • Click the server device → Config tab → set IP address, subnet mask, and default gateway.
  • Go to Services tab → DNS.
  • Toggle DNS service to On.
  • Add A records: enter hostname (e.g. www.kkpapar.edu.my) and the target IP address → click Add.
  • Direct PCs to use this server: set DNS server field in PC IP settings to server's IP.
3.5.4 Verification Methods
  • nslookup <hostname> — queries DNS and returns resolved IP; confirms server is reachable.
  • ping www.kkpapar.edu.my — tests both DNS resolution AND Layer 3 connectivity.
  • On Cisco router: ping <hostname> uses configured name-server.
  • Troubleshoot: check ip name-server, firewall rules blocking UDP 53, and A record spelling.

Key Concepts
ℹ️
DNS Record Types: A record = hostname → IPv4; AAAA = hostname → IPv6; CNAME = alias; MX = mail server; PTR = reverse lookup (IP → hostname).
✅
Disable domain lookup on routers in labs: Use no ip domain-lookup to prevent the router from treating mistyped commands as hostnames and hanging for 30 seconds.
⚠️
DNS vs DHCP DNS option: Even if DHCP pushes a DNS server IP, the host must have Layer 3 connectivity to that server for DNS to work. Verify the route exists first.
🔧
Packet Tracer Limitation: Packet Tracer's DNS server is simplified — it supports A and CNAME records only. Use a real BIND or Windows DNS server for full record type testing.

Cisco IOS Configuration Examples
Router DNS commands and Packet Tracer server setup

Example 1 — DNS Configuration on a Cisco Router

! ── Enable DNS lookup (on by default)
Router(config)# ip domain-lookup

! ── Set the local domain name
Router(config)# ip domain-name kkpapar.edu.my

! ── Point router to DNS server(s)
Router(config)# ip name-server 192.168.1.100 8.8.8.8

! ── Verify — router now resolves hostnames
Router# ping www.kkpapar.edu.my

! ── Disable lookup to avoid CLI typo delays in labs
Router(config)# no ip domain-lookup

Example 2 — Packet Tracer DNS Server Setup (Step-by-Step)

Step 1: Select DNS server PC/Server in topology
Step 2: Config tab → FastEthernet0
  IP Address  : 192.168.1.100
  Subnet Mask : 255.255.255.0
  Gateway     : 192.168.1.1

Step 3: Services tab → DNS → Toggle ON
Step 4: Add A records:
  Name : www.kkpapar.edu.my  Address : 192.168.1.200
  Name : ftp.kkpapar.edu.my  Address : 192.168.1.201

Step 5: On each PC → Config → DNS Server = 192.168.1.100
Step 6: PC Command Prompt → nslookup www.kkpapar.edu.my
Step 7: PC Command Prompt → ping www.kkpapar.edu.my

Hands-on lab
🖥️ Lab 6 — DNS Configuration on Router and Server

Open the Lab 6 Packet Tracer file. Complete the following steps:

  1. Build a topology: Router0, Switch, DNS Server (Server0), Web Server (Server1), two PCs.
  2. Assign static IP addresses — DNS Server: 192.168.1.100, Web Server: 192.168.1.200, PCs and router on 192.168.1.0/24.
  3. On Server0 (DNS): go to Services → DNS → turn ON → add A record www.lab.local → 192.168.1.200.
  4. On Server1 (Web): go to Services → HTTP → turn ON; leave default page.
  5. On each PC, configure DNS server = 192.168.1.100.
  6. From PC0 command prompt, run nslookup www.lab.local — verify IP returned matches 192.168.1.200.
  7. From PC0 open Web Browser → type http://www.lab.local — verify page loads.
  8. On the router, configure ip name-server 192.168.1.100 and test ping www.lab.local from router console.
