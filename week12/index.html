4.1.1 Why Network Monitoring Matters
  • SLA (Service Level Agreement): Defines agreed uptime, latency, and performance guarantees between provider and customer.
  • Baseline: A snapshot of normal network behaviour — used to detect anomalies.
  • Proactive monitoring: Detect and fix issues before users are affected.
  • Reactive monitoring: Responding after a user reports a problem — costly and disruptive.
  • Key metrics: bandwidth utilisation, packet loss, latency, interface errors, CPU/memory on devices.
4.1.2 SNMP Architecture
  • Manager: The monitoring station (runs NMS software like PRTG, Zabbix).
  • Agent: Software on each monitored device (router, switch, server) that responds to SNMP queries.
  • MIB (Management Information Base): A hierarchical database defining all manageable objects.
  • OID (Object Identifier): Unique dotted numeric identifier for each MIB object (e.g. 1.3.6.1.2.1.1.1 = sysDescr).
  • Community String: Acts as a password — public (read-only) and private (read-write) are defaults.
  • SNMP uses UDP port 161 (agent) and 162 (trap receiver).
4.1.3 SNMPv1 vs v2c vs v3
  • SNMPv1: Original — community strings sent in plaintext, 32-bit counters only.
  • SNMPv2c: Adds 64-bit counters (critical for Gigabit interfaces), bulk retrieval operations — still plaintext.
  • SNMPv3: Adds authentication (MD5/SHA) and encryption (DES/AES) — use in production.
  • Exam tip: SNMPv3 uses users (not community strings), security levels: noAuthNoPriv, authNoPriv, authPriv.
4.2.1 Telnet vs SSH
  • Telnet (TCP 23): All data including username/password sent in cleartext — vulnerable to eavesdropping.
  • SSH (TCP 22): Encrypted session — prevents credential theft on the network.
  • SSH requires the router to have a hostname, domain name, and RSA key pair generated.
  • Always restrict VTY lines to transport input ssh to block Telnet access.
  • SSHv2 is preferred over SSHv1 (SSHv1 has known weaknesses).
4.2.2 NetFlow Overview
  • NetFlow collects metadata about network flows (src IP, dst IP, ports, protocol, byte count).
  • Exported to a NetFlow collector for analysis — useful for capacity planning and security forensics.
  • Does NOT capture packet contents — just flow statistics.
  • Configured per interface on Cisco with ip flow ingress / ip flow egress.

Key Concepts
ℹ️
SNMP Trap vs Poll: Polling = manager asks agent periodically. Trap = agent proactively alerts manager when a threshold is crossed (e.g. interface down). Traps reduce polling overhead.
✅
SSH Pre-Requisites: Before generating RSA keys you MUST have a hostname (hostname R1) and domain name (ip domain-name kkpapar.my) set — IOS uses these to create the key name.
⚠️
Default Community Strings are a Security Risk: Change public and private community strings immediately. These are well-known and can be exploited for SNMP enumeration attacks.
🔧
Minimum RSA Key Size: Use at least 1024 bits for SSH compatibility — IOS SSH requires a minimum of 768 bits. Use 2048 bits in production environments.

Cisco IOS Configuration Examples
Full SSH setup and SNMP community string config

Example 1 — Full SSH Configuration on a Router

! ── Step 1: Set hostname and domain name (required for RSA key)
Router(config)# hostname R1
R1(config)# ip domain-name kkpapar.my

! ── Step 2: Create a local user account
R1(config)# username admin privilege 15 secret Cisco123!

! ── Step 3: Generate RSA key pair (1024-bit minimum)
R1(config)# crypto key generate rsa modulus 1024

! ── Step 4: Enable SSH version 2
R1(config)# ip ssh version 2

! ── Step 5: Configure VTY lines to use SSH only
R1(config)# line vty 0 4
R1(config-line)# login local
R1(config-line)# transport input ssh

! ── Verify SSH
R1# show ip ssh
R1# show ssh

Example 2 — SNMP Configuration

! ── Configure SNMP community strings
R1(config)# snmp-server community KKPread RO
R1(config)# snmp-server community KKPwrite RW

! ── Set device location and contact info
R1(config)# snmp-server location "Server Room, Block A, KK Papar"
R1(config)# snmp-server contact jusdy@kkpapar.edu.my

! ── Enable SNMP traps to NMS station
R1(config)# snmp-server host 192.168.100.5 version 2c KKPread
R1(config)# snmp-server enable traps

! ── Verify
R1# show snmp
