4.3.1 Overview of Monitoring Tools
  • Wireshark: Free, open-source packet analyser — captures and dissects network traffic in real time.
  • PRTG Network Monitor: Commercial (free for ≤100 sensors) — GUI-based, SNMP polling, bandwidth graphs, alerts.
  • Nagios: Open-source — host and service monitoring with plugin-based architecture, alert emails.
  • Zabbix: Open-source — agent-based and agentless monitoring, auto-discovery, templates, dashboards.
  • SolarWinds NPM: Enterprise-grade — advanced topology maps, deep SNMP, NCM for config management.
4.3.2 Installing & Configuring a Monitoring Tool
  • Install PRTG or Zabbix on a dedicated management station (Windows Server or Linux).
  • Add network device: enter IP address, select SNMP version, enter community string.
  • Tool auto-discovers interfaces and creates sensors for bandwidth, CPU, memory.
  • Set alert thresholds — e.g. alert when interface bandwidth > 80%.
  • Configure notification channels: email, SMS, or webhook.
4.3.3 Using Wireshark
  • Select the capture interface (e.g. Ethernet, Wi-Fi) and click the shark-fin icon to start.
  • Capture filter (applied before capture): e.g. host 192.168.1.1, port 80 — reduces volume.
  • Display filter (applied after capture): e.g. http, dns, tcp.port == 443 — filters view.
  • Packet pane: Frame details, Ethernet, IP, TCP/UDP, and application layer decoded.
  • Follow Stream: right-click → Follow → TCP Stream — reassembles conversation.
4.3.4 Generating a Network Monitoring Report
  • Device List: All monitored devices with IP, role, and status.
  • Interface Statistics: Bandwidth utilisation graphs per interface over reporting period.
  • Alert Log: All triggered alerts — timestamp, device, severity, duration.
  • Findings: Analysis of observed anomalies or performance degradation.
  • Recommendations: Actions to resolve or prevent recurrence.

Key Concepts
ℹ️
Packet Capture Ethics: Only capture traffic on networks you own or have explicit written permission to monitor. Capturing traffic without authorisation is illegal under Malaysia's Computer Crimes Act 1997.
✅
Establish a Baseline First: Before setting alert thresholds, capture 1–2 weeks of normal traffic to understand typical bandwidth, CPU, and error rates. Thresholds based on baselines are far more accurate.
⚠️
Threshold Setting: Setting thresholds too low causes alert fatigue — staff begin ignoring alerts. Too high means real problems go undetected. Use % of capacity (e.g. 80% utilisation) rather than absolute values.
🔧
Wireshark Capture Filter Syntax: Uses BPF (Berkeley Packet Filter) syntax — different from display filters. Example: tcp port 80 and host 192.168.1.5 captures only HTTP from/to that host.

Wireshark Capture Exercise
Capturing and filtering HTTP traffic — step-by-step
ℹ️
This exercise uses Wireshark on a Windows/Linux management station connected to the lab network.
Step 1: Open Wireshark and select the active network interface

Step 2: Set a capture filter BEFORE starting capture
  Capture Filter: tcp port 80

Step 3: Click the blue shark-fin button (Start Capture)

Step 4: Open a web browser and visit http://www.kkpapar.edu.my

Step 5: Stop capture after page loads (red square button)

Step 6: Apply a display filter to show only HTTP GET requests
  Display Filter: http.request.method == "GET"

Step 7: Click on a packet — expand layers in the detail pane
  - Frame → Ethernet II → Internet Protocol → TCP → HTTP
  - Note the Host header in the HTTP layer

Step 8: Right-click any TCP packet → Follow → TCP Stream
  - Observe the full HTTP request/response conversation
