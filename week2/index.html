1.3 What is a NOC and its Core Functions
  • A NOC is a centralised location where IT professionals monitor, manage, and maintain network infrastructure 24/7.
  • Core functions: network monitoring, incident management, performance management, patch and update management, backup & recovery oversight.
  • NOC operators use dashboards showing real-time status of all monitored devices and links.
  • Service Level Agreements (SLAs) define the response and resolution times that the NOC must meet.
  • Common NOC tools: Nagios, PRTG, SolarWinds, ServiceNow, PagerDuty, Splunk.
1.3 NOC Team Roles — Tier Structure
  • Tier 1 Engineer: First responder. Monitors dashboards, acknowledges alerts, performs basic troubleshooting (ping, port check, restart service). Escalates if unresolved in SLA timeframe.
  • Tier 2 Engineer: Advanced troubleshooting. Has deeper network/system knowledge. Handles escalations from Tier 1. Can make config changes on devices.
  • Tier 3 Engineer: Expert-level. Handles complex issues, works with vendors, designs solutions. May interface with engineering team for persistent problems.
  • NOC Manager: Oversees operations, manages team schedules (shifts), reviews SLA compliance, escalates to senior management, coordinates with clients.
1.3 NOC vs SOC — Key Differences
  • NOC focus: Availability, performance, uptime. Deals with hardware failures, link outages, latency, software bugs.
  • SOC focus: Security threats. Deals with intrusion attempts, malware, data breaches, vulnerability management.
  • Both operate 24/7 and use monitoring platforms, but their alert types and response playbooks are different.
  • In large enterprises, NOC and SOC are separate teams. In SMEs, one team often handles both.
  • A NOC engineer and a SOC analyst may both see a DDoS attack alert, but their response actions differ.
1.4 Best Practices — Documentation & Change Management
  • Documentation: Maintain up-to-date network diagrams (physical and logical), device inventory, IP address plan (IPAM), and configuration archives.
  • Change Management: All changes must follow a formal process — Request → Approval → Testing → Implementation → Review. Prevents unauthorised changes that could cause outages.
  • Use a Change Advisory Board (CAB) for high-risk changes. Emergency changes bypass CAB but must be documented post-implementation.
  • Tools: ServiceNow, Jira, Confluence (documentation), ManageEngine (change management).
1.4 Best Practices — Monitoring, Security & ITIL
  • Monitoring: Use SNMP, syslog, and NetFlow for continuous visibility. Set thresholds for CPU, memory, bandwidth, and interface errors. Alert on anomalies immediately.
  • Security hardening: Disable unused ports and services, use strong passwords, enable SSH over Telnet, apply ACLs, keep firmware updated.
  • ITIL (Information Technology Infrastructure Library): A framework for IT service management. Key processes relevant to networking: Incident Management, Problem Management, Change Management, Service Level Management.
  • ITIL helps ensure the NOC operates consistently and that recurring issues (problems) are addressed at their root cause, not just symptom level.

Key Concepts & Study Notes
Important points for CLO1 assessment
📌
Escalation Path: Tier 1 → Tier 2 → Tier 3 → Vendor/Engineering. Escalation happens when: (1) the issue is not resolved within the SLA timeframe, (2) the engineer lacks the access or knowledge to proceed, or (3) the issue requires a configuration change above the current tier's authority.
✅
ITIL Incident vs Problem: An Incident is a single unplanned interruption (e.g., link went down). A Problem is the underlying root cause of multiple incidents (e.g., faulty SFP module that keeps causing link flaps). NOC handles incidents; Problem Management looks for root causes.
⚠️
Exam tip: Know the distinction between NOC and SOC clearly. Know all 4 tier roles including the NOC Manager. Understand why documentation and change management are considered "best practices" — they prevent outages and aid in audits.
