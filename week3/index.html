2.1 What is a VLAN and Why Use It?
  • A VLAN (Virtual Local Area Network) is a logical grouping of network devices that act as if they are on the same physical network segment, regardless of physical location.
  • VLANs are configured on Layer 2 switches and operate within the data-link layer (OSI Layer 2).
  • Without VLANs, all devices on a switch share the same broadcast domain — this creates performance and security problems as networks grow.
  • Key benefits: (1) Segmentation — reduces broadcast domains; (2) Security — isolates sensitive traffic; (3) Flexibility — users can be in the same VLAN regardless of physical switch port; (4) Performance — less broadcast traffic per segment.
  • To route traffic between VLANs, a Layer 3 device (router or Layer 3 switch) is required.
2.1 VLAN Types — Default, Data, Voice
  • Default VLAN (VLAN 1): All switch ports belong to VLAN 1 by default. Cannot be renamed or deleted. Best practice is to move all user traffic off VLAN 1 for security (VLAN 1 carries CDP, VTP, PAgP, LACP by default).
  • Data VLAN: Configured to carry user-generated data traffic (e.g., VLAN 10 for HR, VLAN 20 for Finance). Separates different user groups.
  • Voice VLAN: A special VLAN configured on access ports to support IP phones. Provides QoS (priority queuing) to voice traffic. The access port carries both a data VLAN and a voice VLAN simultaneously using 802.1Q tagging for the voice traffic.
2.1 VLAN Types — Native, Management, Reserved
  • Native VLAN: The VLAN whose traffic is sent untagged over a trunk link. Default native VLAN is VLAN 1. Must match on both ends of a trunk or a "native VLAN mismatch" error occurs. Best practice: change native VLAN to an unused VLAN to prevent VLAN hopping attacks.
  • Management VLAN: Used to access the switch via SSH/Telnet/SNMP. An SVI (Switched Virtual Interface) is configured on this VLAN with an IP address. Should not be VLAN 1 for security. Example: VLAN 99 as management VLAN.
  • Reserved VLANs: Cisco reserves VLANs 1002–1005 for Token Ring and FDDI compatibility. These cannot be used for Ethernet. Extended VLAN range is 1006–4094.
2.1 VLAN Trunking and IEEE 802.1Q
  • A trunk link carries traffic from multiple VLANs between switches (or between a switch and a router).
  • IEEE 802.1Q is the industry-standard trunking protocol. It inserts a 4-byte tag into the Ethernet frame header identifying which VLAN the frame belongs to.
  • The 802.1Q tag contains: TPID (0x8100), Priority bits (3 bits for QoS), DEI bit, VLAN ID (12 bits — supports up to 4094 VLANs).
  • Access port: Assigned to exactly one VLAN. Connects to end devices (PCs, printers). Frames are untagged on access ports.
  • Trunk port: Carries multiple VLANs simultaneously. Connects switch-to-switch or switch-to-router. Frames are tagged with VLAN IDs (except native VLAN traffic).

Key Concepts & Study Notes
Important points for CLO1 assessment
📌
VLAN Range Summary: Normal range: 1–1005 (stored in flash as vlan.dat). Extended range: 1006–4094 (stored in running-config only). Reserved by Cisco: 1002–1005. VLAN 1: default (cannot delete). VLAN 1006–4094: extended range, requires VTP transparent mode.
✅
802.1Q Frame Tag: The tag is inserted between the source MAC address field and the EtherType field. The VLAN ID field is 12 bits long, which is why the maximum number of VLANs is 2¹² = 4096 (IDs 0 and 4095 are reserved, leaving 4094 usable).
⚠️
Security Best Practice: Always change the native VLAN from VLAN 1 to an unused VLAN. This prevents "VLAN hopping" attacks where an attacker crafts double-tagged 802.1Q frames to jump into the native VLAN traffic. Also move management off VLAN 1.
