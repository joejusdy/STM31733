Sub-topic Details
Expand each section for detailed notes
3.1 Cisco IOS CLI Modes
  • User EXEC Mode: Prompt is Router>. Limited commands — show version, ping, traceroute. Cannot make configuration changes. Entry point when you first connect to a device.
  • Privileged EXEC Mode: Prompt is Router#. Full show commands, copy, reload, debug. Enter from User EXEC with enable command. Exit with disable.
  • Global Configuration Mode: Prompt is Router(config)#. Enter from Privileged EXEC with configure terminal (or conf t). Changes apply to the entire device.
  • Interface Configuration Mode: Prompt is Router(config-if)#. Enter from Global Config with interface <type> <number>. Changes apply to that specific interface.
  • Other sub-modes: Line config (config-line)#, Router config (config-router)#
  • Use exit to go back one level, end or Ctrl+Z to return directly to Privileged EXEC.
3.1 Passwords — enable secret vs enable password
  • enable password <password>: Stored as plain text in the running-config (unless service password-encryption is set, which applies a weak Type 7 encryption). Legacy command — avoid in production.
  • enable secret <password>: Stored as a one-way MD5 hash (Type 5) in the running-config. Cannot be reversed. If both are set, enable secret always takes precedence.
  • Best practice: Always use enable secret and never rely on enable password alone. Combine with service password-encryption for all other passwords.
3.1 Line Authentication — Console and VTY
  • Console line (line con 0): Physical access via RJ-45 rollover cable or USB. Configure with line con 0. Set password, enable login (uses line password) or login local (uses local username database). Set exec-timeout to auto-logout idle sessions.
  • VTY lines (line vty 0 4): Virtual terminal lines for Telnet/SSH access. Up to 16 VTY lines (0–15) on most devices. Configure with line vty 0 4. Use login local for username/password auth. Use transport input ssh to allow only SSH (not Telnet).
  • Local user database: Created with username <name> secret <password> in Global Config. Used when login local is configured on lines.
3.1 MOTD Banner and Saving Configuration
  • MOTD Banner: banner motd #<message># — Displays a message before the login prompt. Used for legal warning notices ("Authorized users only. Unauthorised access is prohibited.").
  • Running-config: The current active configuration stored in RAM. Lost on reboot if not saved.
  • Startup-config: Saved configuration stored in NVRAM. Loaded on boot.
  • Save command: copy running-config startup-config (long form) or write memory / wr (shorthand). Both save the running-config to NVRAM.
  • Verify: show running-config — view active config. show startup-config — view saved config.

Cisco IOS — Full Initial Configuration Example
Complete initial setup for a router or switch (Subtopic 3.1)
🔵
Apply these commands to both routers and switches. For a switch, replace interface GigabitEthernet0/0 with the management SVI interface vlan 1 (or your management VLAN). The password and authentication commands are identical.
! ── Step 1: Enter Privileged EXEC mode ──
Router>
Router> enable
Router# 

! ── Step 2: Enter Global Configuration mode ──
Router# configure terminal
Router(config)#

! ── Step 3: Set hostname ──
Router(config)# hostname KKP-Router1
KKP-Router1(config)#

! ── Step 4: Disable DNS lookup (prevents delay on typos) ──
KKP-Router1(config)# no ip domain-lookup

! ── Step 5: Set enable secret (privileged EXEC password) ──
KKP-Router1(config)# enable secret Admin@12345

! ── Step 6: Create local user account ──
KKP-Router1(config)# username admin privilege 15 secret P@ssw0rd

! ── Step 7: Encrypt all plaintext passwords ──
KKP-Router1(config)# service password-encryption

! ── Step 8: Configure MOTD banner ──
KKP-Router1(config)# banner motd #
***********************************************
*  AUTHORISED ACCESS ONLY                     *
*  Kolej Komuniti Papar — KKP Network         *
*  Unauthorised access will be prosecuted     *
***********************************************
#

! ── Step 9: Configure console line authentication ──
KKP-Router1(config)# line con 0
KKP-Router1(config-line)# login local
KKP-Router1(config-line)# exec-timeout 5 0
KKP-Router1(config-line)# logging synchronous
KKP-Router1(config-line)# exit

! ── Step 10: Configure VTY lines (SSH access) ──
KKP-Router1(config)# line vty 0 4
KKP-Router1(config-line)# login local
KKP-Router1(config-line)# transport input ssh
KKP-Router1(config-line)# exec-timeout 5 0
KKP-Router1(config-line)# exit

! ── Step 11: Configure SSH (requires domain name and RSA key) ──
KKP-Router1(config)# ip domain-name kkpapar.edu.my
KKP-Router1(config)# crypto key generate rsa modulus 2048
KKP-Router1(config)# ip ssh version 2

! ── Step 12: Configure management interface (router) ──
KKP-Router1(config)# interface GigabitEthernet0/0
KKP-Router1(config-if)# ip address 192.168.1.1 255.255.255.0
KKP-Router1(config-if)# description Link to Core Switch
KKP-Router1(config-if)# no shutdown
KKP-Router1(config-if)# end

! ── Step 13: Save configuration ──
KKP-Router1# copy running-config startup-config
! or simply:
KKP-Router1# wr

! ── Verification commands ──
KKP-Router1# show running-config
KKP-Router1# show version
KKP-Router1# show ip interface brief

Packet Tracer Lab Activity
Hands-on practice — Practical 1 component
🖥️ Lab 1 — Configure a Cisco Router and Switch from Scratch

Open Cisco Packet Tracer and build the topology: 1 Router (2811 or ISR4321) + 1 Switch (2960) + 2 PCs. Follow the steps below to complete the initial configuration.

  1. Build the topology: connect PC0 and PC1 to the switch (Fa0/1 and Fa0/2), connect Switch Fa0/24 (or G0/1) to Router Gi0/0 using a straight-through cable.
  2. On the Router: enter Privileged EXEC mode (enable), then Global Config (conf t). Set hostname to KKP-Router1.
  3. Configure enable secret Admin@12345. Create a local user: username admin privilege 15 secret P@ssw0rd. Enable service password-encryption.
  4. Configure the MOTD banner with a legal warning message using banner motd #.
  5. Configure console line 0 with login local and exec-timeout 5 0. Configure VTY lines 0–4 with login local and transport input ssh.
  6. Assign IP address 192.168.1.1/24 to GigabitEthernet0/0. Use no shutdown to bring the interface up. Verify with show ip interface brief.
  7. On the Switch: repeat hostname, enable secret, local user, password encryption, MOTD, console, and VTY configuration steps. Configure the management SVI: interface vlan 1 → IP 192.168.1.2/24 → no shutdown. Set the default gateway: ip default-gateway 192.168.1.1.
  8. Assign IP addresses to PC0 (192.168.1.10/24) and PC1 (192.168.1.20/24) with default gateway 192.168.1.1. Test connectivity by pinging between PCs and to the router. Save all configurations with wr.

Key Concepts & Study Notes
Critical points for CLO2 practical assessment
📌
IOS Mode Prompts Summary: Router> = User EXEC · Router# = Privileged EXEC · Router(config)# = Global Config · Router(config-if)# = Interface Config · Router(config-line)# = Line Config. The prompt always tells you which mode you are in.
✅
enable secret always wins: If both enable password and enable secret are configured, enable secret is always used. Never set enable password in production. The secret is stored as an MD5 hash — it cannot be recovered, only reset.
⚠️
Always save your config! Running-config lives in RAM and is lost on power cycle. Use copy running-config startup-config or wr after every significant change. In a lab, forgetting to save is the most common mistake — your topology may reset between sessions.
🔵
SSH requirement: To enable SSH, the device needs: (1) a hostname set, (2) an IP domain name (ip domain-name), (3) an RSA key (crypto key generate rsa modulus 2048), (4) ip ssh version 2. SSH uses TCP port 22; Telnet uses TCP port 23. Always use SSH in practice.
