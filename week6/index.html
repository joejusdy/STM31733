Sub-topic Details
Expand each section for detailed notes
3.2 Creating VLANs and Naming Them
  • VLANs are created from Global Config mode using vlan <id>. This puts you into VLAN config mode where you can assign a name.
  • VLAN information is stored in the vlan.dat file on flash memory — it persists separately from the running-config.
  • To delete a VLAN: no vlan <id>. Warning: ports assigned to a deleted VLAN become inactive until reassigned.
  • Recommended VLAN naming convention: use descriptive names like SALES, MGMT, IT, VOICE in uppercase.
  • Verify created VLANs with show vlan brief.
3.2 Assigning Ports to VLANs (Access Mode)
  • Access ports carry traffic for a single VLAN and connect to end devices (PCs, printers, IP phones).
  • Configure: enter interface config → switchport mode access → switchport access vlan <id>.
  • Use interface range to configure multiple ports simultaneously (e.g., interface range fa0/1 - 10).
  • Always add a description to document what is connected: description PC-SALES-01.
  • Verify port VLAN assignment with show vlan brief or show interfaces fa0/1 switchport.
3.2 Management VLAN SVI Configuration
  • An SVI (Switched Virtual Interface) is a logical Layer 3 interface on a switch. It allows the switch to be managed via IP (SSH, Telnet, SNMP).
  • The Management VLAN SVI is created with interface vlan <id> and assigned an IP address.
  • The switch also needs a default gateway configured for management traffic to reach other networks: ip default-gateway <ip>.
  • Best practice: Use a dedicated VLAN for management (not VLAN 1). Common choices: VLAN 99, VLAN 100.
  • Ensure at least one port is in the management VLAN, or the switch will be inaccessible remotely.
3.2 Trunk Port Configuration
  • Trunk ports carry tagged VLAN traffic between switches (or switch to router). They allow all VLANs by default unless restricted.
  • Configure: switchport mode trunk on both ends of the inter-switch link.
  • Optionally restrict which VLANs are allowed: switchport trunk allowed vlan <list>.
  • Change the native VLAN (security best practice): switchport trunk native vlan <id>. Must match on both ends.
  • Verify: show interfaces trunk shows mode, encapsulation, native VLAN, and allowed VLANs.
  • DTP (Dynamic Trunking Protocol) can auto-negotiate trunk links — disable it in production with switchport nonegotiate.

Cisco IOS — VLAN & Trunk Configuration Examples
Complete VLAN setup on a Cisco 2960 switch (Subtopic 3.2)
! ══════════════════════════════════════════
! PART 1: Create VLANs
! ══════════════════════════════════════════
Switch(config)# vlan 10
Switch(config-vlan)# name SALES
Switch(config-vlan)# exit

Switch(config)# vlan 20
Switch(config-vlan)# name IT
Switch(config-vlan)# exit

Switch(config)# vlan 30
Switch(config-vlan)# name FINANCE
Switch(config-vlan)# exit

Switch(config)# vlan 99
Switch(config-vlan)# name MGMT
Switch(config-vlan)# exit

! ══════════════════════════════════════════
! PART 2: Assign access ports to VLANs
! ══════════════════════════════════════════
Switch(config)# interface range FastEthernet0/1 - 8
Switch(config-if-range)# description SALES-PCs
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 10
Switch(config-if-range)# exit

Switch(config)# interface range FastEthernet0/9 - 16
Switch(config-if-range)# description IT-PCs
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 20
Switch(config-if-range)# exit

Switch(config)# interface range FastEthernet0/17 - 22
Switch(config-if-range)# description FINANCE-PCs
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 30
Switch(config-if-range)# exit

! ══════════════════════════════════════════
! PART 3: Management VLAN SVI configuration
! ══════════════════════════════════════════
Switch(config)# interface vlan 99
Switch(config-if)# description Management Interface
Switch(config-if)# ip address 192.168.99.2 255.255.255.0
Switch(config-if)# no shutdown
Switch(config-if)# exit

Switch(config)# ip default-gateway 192.168.99.1

! ══════════════════════════════════════════
! PART 4: Configure trunk port (uplink to router or another switch)
! ══════════════════════════════════════════
Switch(config)# interface GigabitEthernet0/1
Switch(config-if)# description Uplink to Core Router
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk native vlan 999
Switch(config-if)# switchport trunk allowed vlan 10,20,30,99
Switch(config-if)# switchport nonegotiate
Switch(config-if)# end

! ══════════════════════════════════════════
! PART 5: Verify configuration
! ══════════════════════════════════════════
Switch# show vlan brief
Switch# show interfaces trunk
Switch# show interfaces GigabitEthernet0/1 switchport
Switch# show running-config
Switch# wr

Hands-on practice — Practical 2 component
🖥️ Lab 2 — VLAN Configuration and Trunking

Topology: 2 Cisco 2960 switches (SW1 and SW2) connected via a trunk link (G0/1 on each). Attach 2 PCs per VLAN per switch (VLANs 10, 20, 30). One PC in VLAN 99 for management testing.

  1. Build topology: SW1 ↔ SW2 trunk on G0/1. Connect 6 PCs to SW1 (2 per VLAN: Fa0/1-2 → VLAN 10, Fa0/3-4 → VLAN 20, Fa0/5-6 → VLAN 30). Mirror configuration on SW2.
  2. On SW1: create VLANs 10 (SALES), 20 (IT), 30 (FINANCE), 99 (MGMT). Verify with show vlan brief — confirm all 4 VLANs appear.
  3. Assign access ports on SW1: Fa0/1-2 to VLAN 10, Fa0/3-4 to VLAN 20, Fa0/5-6 to VLAN 30. Add descriptive description to each port range.
  4. Configure the Management VLAN 99 SVI on SW1: interface vlan 99 → IP 192.168.99.2/24 → no shutdown. Set default gateway to 192.168.99.1.
  5. Configure the trunk port on SW1 G0/1: switchport mode trunk, native VLAN 999, allowed VLANs 10,20,30,99, switchport nonegotiate.
  6. Repeat steps 2–5 on SW2 (use IP 192.168.99.3/24 for SW2 management SVI).
  7. Assign IP addresses to all PCs within their respective VLAN subnets: VLAN 10 → 192.168.10.x/24, VLAN 20 → 192.168.20.x/24, VLAN 30 → 192.168.30.x/24.
  8. Test: Ping between PCs in the same VLAN across switches (should succeed). Ping between PCs in different VLANs (should fail — no inter-VLAN routing yet). Verify trunking with show interfaces trunk on both switches. Save all configurations.

Key Concepts & Study Notes
Critical points for CLO2 practical assessment
📌
vlan.dat vs running-config: VLANs are stored in flash:/vlan.dat — separate from running-config. This means copy running-config startup-config does NOT save VLANs. However, VLANs persist across reboots automatically because vlan.dat is in flash. To delete all VLANs, delete the vlan.dat file: delete flash:vlan.dat.
✅
show vlan brief output: Shows VLAN ID, name, status, and which ports are assigned. Ports NOT listed under a VLAN are either trunk ports or inactive. If a port appears under VLAN 1, it has not been assigned to another VLAN yet.
⚠️
Native VLAN mismatch: If the native VLAN configured on each end of a trunk does not match, Cisco switches will generate CDP and syslog warnings. Traffic may still pass but it creates a security risk (VLAN hopping). Always ensure native VLANs match on both ends and use an unused, unrouted VLAN as native.
